# SMO.H3 Studio 0.1.4 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 修复 ComfyUI 超时后遗留任务和真实队列反馈，提供整个窗口的圆角与窗口控制，并把分辨率改为 H3 实际输出像素。

**架构：** `ComfyClient` 以可选第三阶段回调上报队列状态，保留现有帧进度回调；生成器把阶段与帧进度合并进原 metadata。窗口控制使用独立、严格的 Electron IPC，不经过生成服务。像素计算用共享纯函数精确复刻 H3 节点，工作流参数不变。

**技术栈：** Electron、React、TypeScript、Zod、Node:sqlite、ComfyUI HTTP/WebSocket、Vitest、Playwright、electron-builder。

## 文件结构与职责

- `src/main/comfy.ts`：队列对账、阶段回调、无进展/总超时、按 `promptId` 精确取消。
- `src/main/generation.ts`：把阶段写入作品 metadata，并在取消/超时时使用精确取消。
- `src/shared/types.ts`：`WorkStage` 与 `WorkExecutionState` 类型。
- `src/renderer/ui.ts`：安全读取阶段数据和时长格式化。
- `src/renderer/WorkProgressBar.tsx`、`JobStatus.tsx`、`WorksPage.tsx`：阶段、队列、已用时间和慢任务提示。
- `src/main/window-options.ts`、`src/main/window-controls.ts`、`src/main/index.ts`：无框透明窗口与独立窗口 IPC。
- `src/preload/index.ts`、`src/shared/ipc.ts`：受限的窗口控制 API 类型与桥接。
- `src/renderer/WindowTitlebar.tsx`、`App.tsx`、`styles.css`：标题栏、拖动区、窗口按钮和圆角容器。
- `src/shared/resolution.ts`：H3 实际宽高与 half-to-even 舍入。
- `src/renderer/GenerationOptions.tsx`：用实际 px 替换 MP 标签。
- `tests/`：覆盖核心行为、窗口 IPC、UI 和真实 Electron 布局，不生成新的真实用户视频。

### 任务 1：ComfyUI 队列对账与精确清理

**文件：** `src/main/comfy.ts`、`src/main/generation.ts`、`src/shared/types.ts`、`tests/unit/comfy.test.ts`、`tests/unit/generation.test.ts`、必要的 ComfyUI 测试 fixture

- [ ] **步骤 1：固定类型并编写失败测试**

在 `src/shared/types.ts` 定义：

```ts
export type WorkStage =
  | 'local-queued'
  | 'uploading'
  | 'backend-queued'
  | 'executing'
  | 'sampling'
  | 'finalizing';

export interface WorkExecutionState {
  stage: WorkStage;
  updatedAt: string;
  lastProgressAt: string;
  queuePosition?: number;
}
```

`WorkMetadata` 增加 `execution?: WorkExecutionState`。`src/main/comfy.ts` 增加：

```ts
export interface ComfyExecutionUpdate {
  stage: 'backend-queued' | 'executing' | 'finalizing';
  queuePosition?: number;
}
```

`waitForCompletion` 的第三参数为可选 `onUpdate?: (update: ComfyExecutionUpdate) => void`，原第二参数帧进度不变。

先写测试证明：

```ts
// pending 目标只删除队列，不调用 /interrupt
await client.cancel('pending-prompt');
expect(upstream.requests).toEqual([
  expect.objectContaining({ method: 'POST', url: '/queue', body: { delete: ['pending-prompt'] } }),
]);

// running 目标只中断该任务；目标已不存在时不调用 /interrupt
await client.cancel('running-prompt');
expect(upstream.requests).toContainEqual(
  expect.objectContaining({ method: 'POST', url: '/interrupt' }),
);
```

另覆盖：无进展超时调用 `cancel(promptId)` 后报错；队列位置经第三参数上报；WebSocket 未发 success 时 `/history` 对账仍能完成；目标从 queue 消失且 history 不存在时经过连续 2 次对账后明确失败，而不是永久等待。

- [ ] **步骤 2：运行测试确认旧行为失败**

运行：`npx vitest run tests/unit/comfy.test.ts tests/unit/generation.test.ts`

预期：`cancel(promptId)` 尚不支持、第三参数不存在、无进展/对账测试失败，旧测试仍能识别兼容性问题。

- [ ] **步骤 3：实现队列解析、对账和双计时器**

构造器新增 `inactivityTimeoutMs = 1_800_000`、`reconcileIntervalMs = 5_000`，现有 `completionTimeoutMs` 默认改为 `7_200_000` 并继续作为总上限。所有时间参数都复用现有正数校验。

`waitForCompletion` 必须：

- 保留现有 WebSocket 事件，收到 `execution_start`/`executing` 时上报 `{ stage: 'executing' }`。
- 上报采样前的 `{ stage: 'backend-queued', queuePosition }`，有帧进度时由生成器切换到 sampling。
- 每 5 秒或测试注入间隔对账 `/queue` 与 `/history`，请求不得重叠；完成/失败后清除 interval、timeout 和 socket。
- 只有阶段、队列位置或帧进度变化才重置无进展计时；不变的轮询不续命。总超时不重置。
- 目标不在 queue 且 history 无结果时允许一次竞态宽限，连续第 2 次仍缺失才失败。
- success 后先上报 `finalizing` 再完成，后续由生成器读取输出。

`cancel(promptId?)` 不传 ID 时保持旧行为；传 ID 时先解析 `/queue`，仅对 pending 目标 `POST /queue { delete: [promptId] }`，仅对 running 目标 `POST /interrupt`，不存在时不发请求。超时和 generation 用户取消都必须使用带 ID 的路径。

- [ ] **步骤 4：在生成 metadata 中合并阶段与进度**

生成器维护当前 `execution` 和最新帧 `progress`，所有写入都使用：

```ts
store.updateWork(workId, {
  metadata: { ...baseMetadata, execution: currentExecution, progress: latestProgress },
});
```

阶段顺序为 local-queued → uploading → backend-queued → executing/sampling → finalizing。`lastProgressAt` 在真正阶段变化、队列变化或新帧时更新；`updatedAt` 与每次状态写入一致。取消和超时使用当前 `submitted.prompt_id`，不能只标记失败后遗留后端任务。

- [ ] **步骤 2：实现共享纯函数**

```ts
export function pythonRoundHalfEven(value: number): number {
  const floor = Math.floor(value);
  const fraction = value - floor;
  if (fraction < 0.5) return floor;
  if (fraction > 0.5) return floor + 1;
  return floor % 2 === 0 ? floor : floor + 1;
}
```

`resolveH3Resolution(aspectRatio, megapixels, multiple = 32)` 使用 `megapixels * 1024 * 1024`、`ASPECT_RATIOS` 和该舍入计算宽高，校验有限正数 MP 与正整数 multiple。
