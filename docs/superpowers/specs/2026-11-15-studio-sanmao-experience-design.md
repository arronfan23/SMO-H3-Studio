# 制作台结果预览、数字模特删除与三脚猫体验设计

日期：2026-11-15

## 已确认范围

- 语音、图像和视频在制作台内直接显示生成结果，"我的作品"继续作为统一仓库。
- 文生视频和图片生视频移除当前模特区域，音频数字人保留。
- 文字生图与参考生图的提示词独立保存，切换不同步。
- 删除数字模特时保留已完成和失败作品；有活动任务时仍禁止删除。
- 三脚猫旧会话本地持久保存，支持打开、选择、删除。
- 三脚猫支持思考档位、图片和文本附件、思考动效及固定底部输入区。
- 设置页采用"运行概览 + 分区工作流"的信息架构。

## 制作台与作品

### 共享结果预览

新增共享 `GenerationResultPreview` 组件，按作品类型复用现有媒体 URL 和预览规则：

- 语音使用原生 `<audio controls>`。
- 图像使用原生 `<img>`，保持自然宽高比和 `object-fit: contain`。
- 视频使用原生 `<video controls>`，保持自然宽高比。

组件只在当前任务完成且输出路径有效时出现，提供"打开目录"和"进入我的作品"操作。运行中继续由 `JobStatus` 展示阶段和进度，不显示伪预览或空白播放器。作品记录只创建一次，制作台预览与仓库读取同一条记录。

### 模特区域

`StudioPage` 仅在 `videoMode === 'audio'` 且存在模特时显示当前模特预览。文生视频和图片生视频不再渲染该区域，布局使用单列制作控制区。音频数字人的模特约束、空状态和参考标签保持不变。

### 独立提示词

`ImageForm` 使用 `textPrompt` 与 `referencePrompt` 两个独立状态和独立输入框 ID。当前模式决定提交哪一个提示词，切换模式只显示对应草稿，不触发另一个状态的赋值。默认、校验、提交锁和重试行为保持。

## 数字模特删除

`Store.deleteAvatar` 改为事务式历史保留：

1. 如果模特存在 pending/running 作品，继续拒绝删除，避免活动工作流失去参考图。
2. 对没有用户标题的已完成/失败作品写入原模特名称，保留历史识别信息。
3. 将这些作品的 `avatarId` 置为 `NULL`，再删除模特记录并提交事务。
4. 事务成功后删除受管目录内的模特照片；照片已不存在时不报错，目录外路径仍拒绝。

保留作品的输出路径、状态、元数据和媒体文件，播放与仓库管理不受影响。不得通过关闭外键检查或删除作品来绕过限制。

## 三脚猫会话

### 本地持久化

新增 `SanmaoConversationStore`，使用应用现有 SQLite 数据库并通过版本化迁移创建会话与消息表：

- 会话：UUID、标题、模型、思考档位、草稿文本、创建时间、更新时间。
- 消息：UUID、会话 ID、角色、正文、创建时间。
- 草稿附件：会话 ID、授权路径、类型、文件名、字节数；图片二进制和文本内容不直接写入数据库。

首次发送时才创建会话，避免空白历史。用户消息立即保存，成功回复完成后保存助手消息；失败或停止时不留下半截助手消息。标题取首条用户消息的前 40 个字符，可打开、选择和删除旧会话，删除前需要确认。

页面切换和软件重启后恢复消息、当前模型、思考档位、草稿和附件。当前正在回复的请求仍只存在内存中，重启后不伪造为已完成。

### 思考与模型

模型切换沿用现有配置存储。思考档位使用三档：

- 快速：`effort: 'low'`。
- 标准：`effort: 'medium'`。
- 深入：`effort: 'high'`。

发送时把当前档位写入 SDK `options.effort`，活动请求不随后续切换改变。回复期间禁用模型和档位切换，切换会话则恢复该会话保存的值。

等待时显示"正在思考/回复"状态与三点动效，使用 `role="status"`，并通过 `prefers-reduced-motion` 关闭动画。

### 底部输入区与附件

页面使用纵向 flex 布局：消息区 `flex: 1; min-height: 0; overflow-y: auto`，输入区 `flex-shrink: 0` 固定底部。无消息时输入区仍位于底部，不随消息增加而被推出视口。

左下角为"添加附件"按钮，支持图片和文本文件，显示数量、名称和移除操作。右下角依次为模型、思考档位和圆形向上发送按钮，回复中变为停止按钮。

附件经 Electron 文件选择与拖放授权，不接受任意路径字符串：

- 图片：PNG、JPEG、WebP，单张不超过 5 MiB，最多 4 张，以 SDK 图片内容块发送。
- 文本：TXT、MD、JSON、CSV、LOG，单份不超过 1 MiB，最多 4 份，以 SDK 文本内容块发送。

`SanmaoQueryInput.prompt` 改为支持 `AsyncIterable<SDKUserMessage>`，消息体使用 `message.content` 文本和图片内容块，不要求开启 Read、Shell 或 MCP 工具。文件只用于当前请求，不进入安装包，不展示完整路径，不上传到其他服务。

## 设置页

采用已选择的"运行概览 + 分区工作流"：

- 顶部全宽状态概览：ComfyUI、硬件摘要、应用版本。
- 主工作区左栏：硬件检测、生成环境、ComfyUI 连接与恢复。
- 主工作区右栏：文字润色和三脚猫 AI 服务，保留现有 tab 和独立配置。
- 模型目录、工作流应用/恢复等高级操作放入次级展开区，下一次生成生效的含义保持明确。
- 窄于 1100px 时改为单栏，操作按钮与保存/错误状态在对应分组内对齐。

不增加嵌套卡片、参数墙、装饰性动效或第二套设置导航。

## 错误与安全

- 活动生成任务使用模特时禁止删除模特；历史作品保留不是删除媒体文件的理由。
- 会话和附件读写失败显示脱敏错误，旧会话仍可打开，不删除其他记录。
- 附件数量、格式、大小和授权都在主进程校验，前端不能绕过。
- SDK 继续保持 `settingSources: []`、`mcpServers: {}` 和独立凭据隔离。

## 测试与验收

- 单元：三种结果预览、独立提示词、模特删除事务、外键有效、旧会话重启恢复、会话删除、思考档位、附件类型/大小/授权、底部布局。
- Electron：各制作页真实输出预览、文生/图生无模特区域、删除模特后作品可播放、旧会话重启、附件实际提交内容块、思考动效与设置页窄窗口。
- 打包：会话存储可写、SDK 可启动、附件和旧会话不包含测试密钥或聊天内容。
- 真实 Claude 连接只使用用户明确提供的授权；没有授权时只报告受控连接错误，不伪造模型或附件调用成功。

## 实施顺序

分别编写三份实现计划，并按以下顺序交付；每份计划都必须包含对应的单元和 Electron 验证：

1. 制作台预览、提示词独立与模特删除。
2. 三脚猫会话持久化、旧会话管理、底部输入区、思考档位和真实附件内容块。
3. 设置页布局及完整单元、Electron、打包回归。
