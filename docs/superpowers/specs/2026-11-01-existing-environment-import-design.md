# SMO.H3 Studio 已有环境导入设计

## 目标

让已经安装 ComfyUI、MiniMax H3 模型和必需自定义节点的用户直接复用现有环境，不再被“首次环境配置”引导去重复下载约 55 GB 文件。

## 用户流程

1. 首次配置页在“开始安装”和“重新检测”之外增加“使用已有环境”按钮。
2. 用户点击后选择现有运行目录，即包含 `python_embeded`、`tools`、`ComfyUI` 和 `docs` 的目录。
3. 软件检测硬件并选择匹配的性能档位，读取现有模型路径配置，校验运行文件和模型，再检查 ComfyUI 健康状态与必需节点。
4. 全部通过后写入 SMO 的 ready 配置并进入制作台。导入过程中不下载、复制、移动或改写现有运行包与模型。
5. 取消目录选择不产生错误；导入中的取消、校验失败或后端失败都会显示明确状态，并保留此前的有效配置。

## 模型定位

- 优先使用结构化 YAML 解析器读取 `<runtimeRoot>/ComfyUI/extra_model_paths.yaml` 中 `h3_selflift_models.base_path`。
- 配置不存在或没有该节时，使用 `<runtimeRoot>/ComfyUI/models`。
- 模型根路径必须是安全的 Windows 绝对路径。`modelDirectory` 记录为 `<modelRoot>/diffusion_models`。
- 按环境清单中的相对路径、文件大小和 SHA256 校验全部 10 个必需模型。缺文件或哈希不符时导入失败，不自动补下载。

## 主进程与 IPC

- `environment:selectExistingRoot`：打开原生目录选择器，返回选中的目录或 `null`。
- `environment:import`：接收 `{ runtimeRoot, profileId }`，通过 `EnvironmentSetupService` 执行导入。
- 导入与安装、重试、硬件检测共用互斥和取消机制，避免并发修改环境状态。
- 导入不检查新安装所需的下载和解压空间，但仍校验 NVIDIA GPU、CUDA 架构、最低显存、内存及所选性能档位。

## 校验与状态

- 运行文件使用现有 `docs/file-manifest.sha256` 校验 Python、启动脚本和 ffprobe。
- 模型校验显示已校验字节数、总字节数和当前文件名；这是读取进度，不显示为下载进度。
- 后端使用现有候选事务机制，验证健康状态和全部必需节点后才激活。
- ready 配置只在文件和后端校验通过后提交。提交后若激活失败，恢复此前的 ready 配置；没有此前配置时记录失败状态，绝不留下未验证的 ready 配置。
- 后续正常启动沿用现有健康检查和节点检查，不重复执行全量模型哈希校验。用户主动重试安装时仍走原有下载安装流程。

## 界面

- 使用现有按钮、图标、进度条和错误区域，不增加新页面或卡片。
- “使用已有环境”只在环境控制器空闲且硬件档位可用时启用。
- 导入阶段复用“校验文件”“启动 ComfyUI”“环境就绪”阶段，不展示“下载运行时”或“下载模型”为当前阶段。

## 测试与验收

- 单元测试覆盖成功导入且下载函数零调用、YAML 模型路径、默认模型路径、缺失或错误模型、非法路径、取消、节点缺失、并发互斥和配置回滚。
- IPC 测试覆盖负载校验、目录选择取消和主进程转发。
- 渲染测试覆盖按钮状态、目录选择取消、导入成功和失败显示。
- E2E 使用隔离目录和模拟后端完成导入，确认不会触发真实下载。
- 完整运行单元测试、类型检查、默认 E2E 和打包态 E2E。
- 最后对 `G:\H3Selflift整合包\ComfyUI_SelfLift_Spark_SM120_CUDA130` 做真实只读导入验收，确认现有模型和节点可用，不生成视频、不停止健康后端。

## 非目标

- 不全盘扫描 ComfyUI，不自动猜测多个候选环境。
- 不迁移或整理用户已有模型，不修改冻结工作流和模型清单。
- 不在本次实现登录、会员或云端环境同步。
