# SMO.H3 Studio 设计规格

日期：2026-10-25  
状态：已确认产品方向与界面结构，待书面规格审查

## 1. 产品定位

SMO.H3 Studio 是 SMO 品牌的 Windows 桌面数字人视频软件。它是在已经配置完成的 ComfyUI 外面增加的一层操作壳，不是另一套推理环境，也不替代 ComfyUI。

软件负责数字模特、素材、提示词润色、任务进度和作品管理。ComfyUI 负责执行已经配置好的工作流、模型、LoRA、VAE、采样器和低显存参数。

第一版交付 Electron 桌面程序与桌面快捷方式。界面采用已确认的 A 方案：左侧导航，中间人物预览，右侧制作控制区。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 软件名称 | SMO.H3 Studio |
| 数字模特 | 用一张照片创建，不进行视频训练 |
| 文字生视频 | 文字与参考图直接交给 MiniMax H3，联合生成画面和声音 |
| 音频数字人 | 上传音频与参考图，生成口型和动作匹配的数字人视频 |
| 独立 TTS | 不提供，不设置文字单独生成音频的功能 |
| 外部 LLM | 只用于调用 H3 Prompt Skills 润色提示词 |
| ComfyUI | 保持为执行后端，不重建、不批量更新、不覆盖模型参数 |
| 硬件适配 | 检测电脑配置并推荐模型与参数，修改前必须获得用户确认 |
| 数据方式 | 本地保存，不上传作品，不加入遥测 |

- 当前工作流配置：INT8 混合主模型、`1152 × 640`、INT8 视频 VAE、低显存注意力、分块前馈和高清自动分块

### 3.2 工作流来源

- 音频数字人底版：`G:\H3Selflift整合包\工作流\Selflift数字人_5080_16GB.json`
- 文字生视频参考：`G:\H3Selflift整合包\工作流\Selflift参考生视频.json`

### 3.3 不依赖的服务

SMO.H3 Studio 不使用 Duix.Avatar、Duix Docker、Fish Speech 或其中的语音库。这些服务可以独立存在，但本软件不启动、停止或修改它们。

## 4. 用户与核心任务

目标用户是在 Windows + NVIDIA 电脑上本地制作数字人视频的人。核心任务如下：

1. 用照片和名称保存数字模特。
2. 选择模特，输入文字，生成带原生声音的视频。
3. 选择模特，上传音频，生成数字人口型视频。
4. 配置外部 LLM，使用官方 H3 Skills 润色提示词。
5. 查看生成进度，播放、重试和管理本地作品。
6. 根据当前电脑配置获得 ComfyUI 模型与参数建议。

## 5. 界面设计

### 5.1 导航

- 「制作台」：创建视频与查看当前任务。
- 「数字模特」：新增、编辑、删除和选择照片模特。
- 「我的作品」：播放、筛选、重试和打开作品目录。
- 「设置」：外部 LLM、ComfyUI 后端、硬件档案和存储位置。

### 5.2 制作台

左侧显示当前模特和预览，右侧提供 2 个模式页签。

「文字生视频」包含：

- 原始文字输入区。
- Skill 选择器，默认「自动选择」。
- 「AI 润色」按钮。
- 「原始文字 / 润色结果」切换与可编辑文本区。
- 视频时长、只读的当前分辨率与硬件配置说明。
- 「使用结果并生成」按钮。

「音频数字人」包含：

- WAV、MP3 等 ComfyUI 可读取音频的上传入口。
- 动作与画面提示词输入区，可使用同一套提示词润色能力。
- 音频截取范围与时长显示。
- 约 2 秒片尾说明和「生成数字人视频」按钮。

不显示声音库、TTS、声音克隆或 Fish Speech 设置。

### 5.3 设置页

外部 LLM 区域包含 `Base URL`、`API Key`、模型选择、「获取模型列表」、「测试模型」和「保存配置」。

ComfyUI 区域包含环境路径、服务地址、2 条工作流路径、「检查后端」和「打开 ComfyUI」。

硬件区域显示 GPU、显存、内存、驱动和推荐配置。推荐只读展示，应用推荐前需要单独确认。

## 6. ComfyUI 工作流集成

### 6.1 壳层契约

- 开发阶段从上述工作流生成 2 份 API 格式模板，软件运行时不依赖前端 UI JSON 作为 `/prompt` 输入。
- 软件只允许替换白名单内容：参考图、音频、提示词、时长、种子、音频截取范围和输出文件名。
- 模型、LoRA、VAE、采样器、调度器、分块和低显存设置全部继承模板。
- 软件不自动更新节点、模型或 Python 依赖。
- 软件绕过本地 Qwen 节点，把原始或润色后的最终提示词直接写入 H3 提示词输入，避免二次改写。
- 软件通过 ComfyUI HTTP API 提交任务，通过 WebSocket 或任务接口跟踪进度并获取结果。

### 6.2 文字生视频

以 `Selflift参考生视频.json` 为来源，使用 `MiniMaxH3ReferenceToVideo` 和 `SelfLiftAvatarH3Sampler`。

- 当前模特照片连接为 `<Picture 1>`。
- 使用参考流程已有的标准 `VAEDecode` 与 `VAEDecodeAudio` 输出路径。
- 不依赖 `MiniMaxH3VAEDecodeFast`、`RAMCleanup` 或 rgthree 辅助节点。
- H3 联合生成视频、对白、环境声和音乐，不生成独立音频文件作为中间步骤。
- 当前 16 GB 工作流参数作为初始模板，其他硬件只通过经过确认的工作流副本调整。

### 6.3 音频数字人

以 `Selflift数字人_5080_16GB.json` 为底版，保留以下处理：

- 上传音频的裁剪、音频 VAE 编码和音视频 latent 拼接。
- 数字人口型与动作生成所需的噪声掩码。
- 输出视频与上传音频的合成。
- 音频结束后预留约 2 秒画面。

时长计算沿用 H3 的 `17k + 5` 帧网格和当前 `+48` 帧片尾设置。软件必须验证计算结果，不能让音频截断镜头结尾。

### 6.4 旁白与多镜头约束

文字模式把目标视频时长传给提示词服务。包含旁白或对白时，提示词必须要求语言内容在镜头结束前约 2 秒说完，结尾只保留环境声、音乐或画面，不得用新增旁白填满片尾。内容过长时应缩短文字，而不是让语言内容冲出镜头。

当前版本只执行单条视频任务。以后若增加多镜头项目，所有镜头必须统一使用 Ref2VA，并共用同一段 `<Audio 1>` 参考人声来锁定音色；该能力不属于第一版交付范围。

## 7. H3 Prompt Skills 与外部 LLM

### 7.1 Skills 来源与使用

软件使用整合包内的 1 个通用 `h3-prompt-writing` 和 8 个风格 Skill。构建时保存一份带版本的 Skills 快照，不自动跟随 ComfyUI 更新。

- 默认自动选择 Skill，也允许手动指定。
- 通用提示词模式遵循 T2VA、I2VA、FL2VA、L2VA 和 Ref2VA 的输入模式规则。
- 当前照片数字人默认使用 Ref2VA，并保持 `<Picture 1>` 等标签一致。
- 风格 Skill 只提供创作指导，最终仍输出单个可执行的 H3 提示词。
- 使用与整合包一致的单次输出约束，禁止 LLM 返回提问、审批步骤、制作建议或后续说明。

### 7.2 输出与校验

Ref2VA 输出必须按顺序包含：

`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。

校验包括：

- 必需字段及顺序。
- 镜头时间戳递增且小于视频时长。
- 用户提供的对白、歌词和画面文字保持原文。
- 不出现 Markdown 围栏、追问、确认请求或额外说明。
- 旁白片尾约束和静音要求。

校验失败时允许自动请求 LLM 修正 1 次。仍失败则保留原文并显示错误，不把无效结果交给 H3。

### 7.3 模型获取与测试

- 「获取模型列表」调用 OpenAI 兼容上游的 `GET /models`。
- 模型列表支持搜索、刷新和按上游配置缓存。
- 上游不支持列表时允许手动输入模型名。
- 「测试模型」对选中的模型发送一条最小 `/chat/completions` 请求。
- 测试结果显示成功、延迟、返回摘要或经过脱敏的错误，不触发 H3 视频生成。
- 请求设置超时；连接失败、鉴权失败、模型不存在和返回格式异常必须分别提示。

### 7.4 密钥与发送范围

- API 请求只由 Electron 主进程发出，渲染进程不能读取密钥。
- API Key 使用 Electron `safeStorage` 在 Windows 上加密保存，不写入明文 SQLite 或日志。
- 发送内容只包括原始文字、视频时长、输入模式和所需 Skill 文档。
- 参考图片、音频、作品和本地文件路径不发送给外部 LLM。
- 外部 LLM 不可用时仍可用原始文字直接生成视频。

## 8. 硬件档案与配置建议

软件检测 Windows 版本、GPU 型号、显存、内存、驱动、CUDA 和可用磁盘空间。

当前 RTX 5080 + 16 GB 显存 + 64 GB 内存使用已验证的 INT8、`1152 × 640`、低显存与自动分块配置。

其他电脑采用以下推荐原则：

- 显存或内存较低：优先 INT8、较低分辨率、较短时长、低显存启动和更多分块。
- 硬件充足：在用户确认后尝试 BF16、较高分辨率或较少分块。
- 推荐前检查对应模型文件是否真实存在；缺失时列出需要补充的模型，不自动下载。
- 不同配置保存为独立硬件档案，不覆盖其他电脑的设置。

软件只解释建议并生成新的工作流副本。只有用户明确确认后才应用副本，原工作流始终保留。

## 9. 数据与存储

- 程序目录：`G:\SMO-H3-Studio`
- 用户数据目录：`G:\SMO-H3-Data`
- 数据目录分别保存模特照片、上传音频、草稿、作品、封面、日志和 SQLite 数据库。

SQLite 记录数字模特、作品、任务、LLM 配置、硬件档案和应用设置。API Key 不以明文存入数据库。

作品记录保存模式、原始与润色提示词、Skill、模型、时长、种子、工作流版本、输出路径、状态和错误信息，便于复现与重试。

## 10. 任务与异常恢复

- 同一时间只执行 1 个 H3 生成任务，其他任务排队。
- ComfyUI 已运行时直接连接；未运行时启动现有环境。
- 软件只停止自己启动的 ComfyUI 进程，不终止已有实例或其他 GPU 应用。
- 取消任务时调用 ComfyUI 中断接口，并保留草稿和任务记录。
- 后端离线、显存不足、模型缺失、磁盘不足、素材缺失和 API 异常分别给出可操作的错误。
- 应用重启后恢复未完成任务状态；已完成输出重新加入作品库，不重复提交相同任务。

## 11. 安全与隐私

- ComfyUI 和本地控制接口只绑定 `127.0.0.1`。
- Electron 启用 `contextIsolation`，关闭渲染进程的 Node.js 集成。
- 文件写入限制在程序数据目录、ComfyUI 输入目录和用户明确选择的输出目录。
- 不上传作品，不加入广告、追踪或遥测。
- 日志不记录 API Key、完整提示词中的敏感内容或本地个人素材内容。

## 12. 验证与验收

### 12.1 自动测试

- Skill 路由、输出字段、时间戳、对白保留和片尾规则。
- 上游模型列表、手动模型、测试成功与常见错误。
- 工作流白名单替换，确保模型与采样参数不被修改。
- 音频时长、`17k + 5` 帧网格和 `+48` 帧片尾计算。
- 不同硬件档案的推荐结果与模型缺失提示。
- API Key 加密、日志脱敏和路径边界。

### 12.2 集成测试

- 使用模拟 LLM 上游验证获取模型、模型测试和润色失败恢复。
- 检查 ComfyUI 节点注册、2 条 API 工作流和模型选项。
- 用用户提供的照片生成 1 条短文字视频，确认画面与声音均存在。
- 用用户提供的照片和音频生成 1 条短数字人视频，确认口型流程、音画同步和片尾。
- 重启软件后确认模特、草稿、设置和作品仍存在。

### 12.3 桌面验收

1. 用户可从桌面快捷方式打开 SMO.H3 Studio。
2. 用户可用一张照片创建数字模特。
3. 用户可配置上游、获取模型列表并测试选中的模型。
4. 用户可选择 Skill、润色并编辑提示词，再生成 H3 视频。
5. 用户可上传音频制作数字人视频。
6. 用户可播放作品、重试任务和打开输出目录。
7. 用户可查看当前硬件配置和对应推荐，且原 ComfyUI 环境不被擅自修改。

其他硬件档位通过配置样例和自动测试验证，不声称已在未实际测试的 GPU 上完成生成验证。

## 13. 第一版不包含

- 实时对话数字人。
- 视频训练数字模特。
- 独立文字转音频、声音克隆或 Fish Speech 集成。
- 多镜头项目管理与多条 H3 任务并行。
- 自动更新 ComfyUI、节点、模型或依赖。
- 云端作品分享、账号体系、广告和遥测。
