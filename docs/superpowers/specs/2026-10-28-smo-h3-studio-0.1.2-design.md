# SMO.H3 Studio 0.1.2 设计规格

日期：2026-10-28

## 背景与目标

本次修复润色请求失败，并完善制作台参数、生成进度、保存状态和品牌视觉。采用用户确认的方案一：复用现有工作流副本和状态体系，不直接修改冻结图，不引入独立 TTS 或 SRT 转写。

已确认的根因与能力：

- 当前 `G:\SMO-H3-Data\llm-config.json` 中的密文无法被 Electron `safeStorage` 解密，必须重新输入 API Key 才能恢复，单纯增加超时不能解决它。
- 完整润色需要长时间生成，`20_000 ms` 的固定超时过短。
- 本机模型目录有 INT8 和 BF16 两个可用模型文件；BF16 尚未实测，默认仍使用 INT8。
- `ResolutionSelector` 支持 8 种比例和 `megapixels`，可通过现有 `HardwareWorkflowStore` 创建独立副本。
- `ComfyClient.waitForCompletion` 已提供真实帧进度回调，作品 `metadata` 可持久化进度，不需要数据库迁移。

## 范围

### 包含

- LLM 密钥重存提示、润色专用超时和保存状态反馈。
- H3 模型、比例、分辨率、画面内字幕的中文可选控件。
- 中文 Skill 名称与说明、真实生成进度条。
- 透明圆形 Logo 和统一四角圆角。
- 自动测试、真实接口验证、0.1.2 portable 与 PR 更新。

### 不包含

- 不导出 SRT，不增加独立音频转写、TTS 或声音克隆。
- 不修改 H3 模型文件、原冻结工作流或启动脚本。
- 不打印、记录或上传用户 API Key；不改动参考图和音频的外发边界。
- 不在本次执行真实用户素材视频生成；本次真实验证限于 LLM 请求和 ComfyUI 健康/节点检查。

## 1. LLM 请求与保存状态

### 凭据异常处理

- `FileLlmConfigStore.getCredentials()` 捕获 `safeStorage` 解密失败，抛出明确错误：密钥无法读取，请在设置页重新输入 API Key。
- `llm:getProfile` 返回 `{ baseUrl, model, keyStatus }`，其中 `keyStatus` 为 `valid` 或 `reenter-required`。新增 `LlmProfileView extends LlmProfile { keyStatus }` 类型，读取损坏配置时不丢失 Base URL 和模型显示值。
- 设置页在 `reenter-required` 状态显示「需要重新输入密钥」，且只有重新输入非空密钥后才能保存。保存成功会覆盖旧密文，状态恢复为 `valid`。

### 请求超时

- `/models` 和模型测试保留 `20_000 ms` 超时，便于快速发现地址和鉴权问题。
- `SkillsService.polish()` 使用的长文本 `chatCompletion` 超时调整为 `120_000 ms`，错误继续脱敏，不伪造成连接错误。
- 超时实现支持按调用覆盖；列表、测试和润色不再共用同一个不可调的等待时间。

### 保存状态

- 当前 Base URL、模型与已保存配置一致，且没有未保存的新密钥输入时，显示带 Check 图标的绿色「已保存」标记。
- 任一字段修改后显示「有未保存修改」。`reenter-required` 优先显示「需要重新输入密钥」。
- 保存成功显示「已保存」，模型测试成功继续单独展示延迟与回复，不与保存状态混用。

## 2. 制作台参数与独立工作流副本

### 控件

- `H3 模型`：`INT8（16GB 推荐）` 为默认；`BF16（大显存候选，未实测）` 为候选，不宣称兼容或已验证。
- `视频比例`：使用中文标签覆盖 `1:1`、`2:3`、`3:2`、`3:4`、`4:3`、`9:16`、`16:9`、`21:9`，值保留 H3 节点原始格式。
- `视频分辨率`：`0.4MP（流畅）`、`0.7MP（标准，默认）`、`1.0MP（高清）`。不虚构具体像素尺寸，最终由 H3 `ResolutionSelector` 计算。
- `生成画面内字幕`：默认关闭。开启时追加与旁白/对白同步、语言一致、画面安全区内可读的字幕指引；关闭时不额外改变用户提示词。

### 生效路径

- `HardwareProfile` 增加可选 `aspectRatio`，沿用 `modelPolicy`、`megapixels`、`lowvram` 和 `tiling`。
- 模型预设保持有效状态机：INT8 使用 `balanced-16gb`，BF16 候选使用 `high-memory-candidate`，使副本文件名与硬件档案一致。
- `applyHardwareProfile` 在 `ResolutionSelector` 上同时应用 `megapixels` 和 `aspectRatio`，模型文件仍由 `selectUnetModel` 校验，禁止自动下载。
- 生成前由 `hardware.apply` 创建并激活当前模式的独立副本，再调用 `jobs.start`。应用失败时不提交生成任务，原冻结文件不变。
- 文字和音频模式分别保存激活配置，重试沿用原 `workflowVersion`，不跟随后续配置切换。
- `GenerationRequest` 增加 `subtitles?: boolean`，只把字幕选择作为提示词补充，不修改 H3 节点模型参数。

### 字幕提示词

- 使用独立的纯函数 `withSubtitlePreference(prompt, enabled, mode)`。
- `enabled=false` 时原样返回，不覆盖用户已有文字。
- `enabled=true` 且没有已有字幕/ caption 指令时，追加一段同步字幕指引；已有相关指令时不重复追加。

## 3. 中文 Skill 与真实进度

### 中文 Skill

- 在渲染层建立 `SkillName -> { title, description }` 映射，原 ID 和路由完全不变。
- 默认项为「自动选择（推荐）」，9 个 Skill 使用与 README 一致的中文名称和一句话说明。
- 当前选中 Skill 的说明显示在下拉框下方，帮助首次使用者理解风格，不展示实现细节。

### 进度数据流

- 在 `GenerationHandler` 调用 `comfy.waitForCompletion` 时，将每次 `{ value, max }` 合并进当前作品的 `metadata.progress`。
- 保留原 `request`、`workflowVersion`、`retryOf` 等字段，每次进度更新只修改 `progress`，不改数据库结构。
- `JobStatus` 和作品列表共用一个小型 `WorkProgressBar`：
  - 后端启动、上传和没有帧进度时显示不确定进度。
  - 收到帧进度后显示 `value / max` 百分比和填充宽度。
  - 完成显示 100%，失败保留最后已知进度，没有进度时显示失败状态。
- 使用 `role="progressbar"`、中文状态文本和正确的 ARIA 数值，避免仅靠颜色表达状态。

## 4. 品牌与圆角

- `prepare-brand.mjs` 用 Sharp 生成圆形 Alpha 蒙版并合成到 512×512 原图，四角 Alpha 为 0，中心保留原图内容；PNG、ICO 和 React 使用同一透明版本。
- 增加资产验证，确认 PNG 尺寸、透明角点和非空中心，不用白底冒充透明。
- 大面板、预览区和弹窗统一 `12px` 圆角，输入框、按钮和小控件统一 `8px` 圆角；保持四角一致，不使用药丸形大按钮。
- 更新侧栏 Logo、制作台、模特、作品、设置和进度条样式，验证 1280×820、960×640 与 200% Zoom 下无溢出或遮挡。
