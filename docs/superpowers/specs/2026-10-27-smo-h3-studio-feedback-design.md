# SMO.H3 Studio 三项交互与后端修复设计

日期：2026-10-27

## 背景与目标

当前版本存在 3 个已确认问题：

- 新建模特时，选择照片后只显示文件名，保存前不能预览或移除。
- 获取 LLM 模型列表被 `baseUrl + model` 条件错误限制，用户必须先填模型才能获取模型。
- 本机 `127.0.0.1:8188` 没有 ComfyUI 监听，应用只提供打开网页，没有启动和等待后端的流程。

采用用户批准的方案 A：按需启动 ComfyUI，并在生成前复用同一健康检查与启动流程。应用打开时不自动启动后端。

## 范围

本次只修改照片选择、模型发现和 ComfyUI 启动相关代码、测试与交付产物。保留现有两条冻结工作流、H3 模型参数、外部 LLM 文本润色边界和其他页面行为。

不做以下事项：

- 不删除用户电脑中的原始照片。
- 不增加独立 TTS、声音克隆或真实外部 LLM 调用。
- 不修改 `G:\H3Selflift整合包` 的工作流、模型或启动脚本。
- 不在软件启动时自动拉起 ComfyUI，不终止已经运行的 ComfyUI 或其他 GPU 进程。
- 不以真实 H3 视频生成作为本次验收；本次只验证真实后端启动、健康检查和节点信息。

## 1. 保存前照片预览与移除

### 交互

- 用户选择照片后，`AvatarsPage` 立即通过现有 `useMediaUrl(photoPath)` 和 `smo-media` 通道显示缩略预览。
- 预览区显示文件名和「移除照片」按钮。移除只把 `photoPath` 设为 `null`，并清除相关预览错误，不调用删除 API，不删除源文件。
- 选择或保存进行中禁用移除操作，避免保存过程更换照片。
- 保存失败后保留名称、照片和预览；保存成功后按现有行为清空表单。

### 实现边界

- 复用 `FileService.selectImage()` 已完成的用户授权和 `MediaRegistry` 媒体令牌，不使用 `file://`，不新增文件系统 IPC。
- 在 `AvatarsPage` 内组合现有 `useMediaUrl`，不修改已保存模特的 `AvatarImage`。
- 移除选择与删除已保存模特是两个独立操作，文案和行为不得混淆。

### 测试

- 选择照片后显示真实授权预览 URL 和图像。
- 移除后恢复未选择状态，保存校验仍要求照片，且没有调用任何删除 API。
- 保存失败不移除预览，保存成功才清空。

## 2. 先获取模型，再选择模型

### 交互

- 「获取模型」只要求非空 `Base URL` 和可用的 API Key，不要求 `model`。
- 获取成功后展示可搜索模型列表，由用户选择；不强制自动选择第一项。
- 保留手动输入模型作为上游列表不可用时的备用路径。
- 「保存设置」和「测试模型」仍要求 `Base URL` 与 `model` 非空。

### 实现边界

- 为 `llm:listModels` 定义独立的发现请求类型和 IPC schema：`baseUrl` 必填，`model` 可省略，`apiKey` 可选。
- 在 LLM 配置存储中增加独立的连接解析方法，用于模型发现。它在 `model` 缺省时仍能解析 Base URL 和 API Key，留空 API Key 时沿用已保存密钥。
- 保存、测试和润色继续使用现有 `resolveCredentials`，要求完整模型配置，避免把空模型带入聊天请求。
- 页面将 `canListModels` 与 `canSave` 分离，不再让 `listModels()` 依赖 `canSave`。

### 测试

- 空模型可以通过 IPC 和配置存储获取模型列表，空 Base URL 仍被拒绝。
- 未保存完整配置时，发现请求可以使用已保存 API Key；不会把媒体内容发送给 LLM。
- 页面空模型时「获取模型」可用，「保存设置」和「测试模型」不可用；选择或手动输入后恢复。

## 3. ComfyUI 按需启动与生成前检查

### 架构

新增主进程 `ComfyProcessManager`，与只做 API 请求的 `ComfyClient` 分离。默认启动目标为：

- Python：`G:\H3Selflift整合包\ComfyUI_SelfLift_Spark_SM120_CUDA130\python_embeded\python.exe`
- 入口：`G:\H3Selflift整合包\ComfyUI_SelfLift_Spark_SM120_CUDA130\tools\launch.py`
- 参数：`-I -X utf8`、`--lowvram`、与 `SMO_COMFYUI_BASE_URL` 一致的 `--port`

支持通过环境变量覆盖启动根目录和入口，便于以后适配其他 SelfLift 包。启动脚本自身继续负责隔离 Python、CUDA、缓存和 FFmpeg 环境。

### 启动流程

1. `ensureReady()` 先调用健康检查；已有健康实例时直接返回，不创建进程。
2. 离线且地址为本机时，用隐藏窗口启动现有 `launch.py`，输出写入应用数据目录下的 `logs/comfyui-backend.log`。
3. 在限定时间内轮询健康检查；成功后返回 `ComfyHealth`。
4. 进程提前退出或超时则失败，并返回不含凭据的日志尾部，方便用户处理。
5. 并发调用共享同一个启动 Promise。成功后保留后端供后续使用；失败后清理启动状态，允许用户重试。

仅支持 `127.0.0.1`、`localhost` 和 `[::1]` 的本机启动。远程地址离线时返回明确错误，不在本机创建替代进程。

应用关闭只停止等待和关闭日志句柄，不终止已有或本次启动的 ComfyUI。下次启动直接复用健康实例。

### IPC 与页面

- 新增严格校验的 `comfy:start` IPC，返回最新健康信息；preload 仅新增对应的 `comfy.start()`。
- 设置页离线时显示「启动 ComfyUI」，启动中显示进度并禁止重复操作，完成后刷新健康状态；失败显示错误。
- 「打开 ComfyUI」继续只打开网页。
- 生成服务在上传素材前调用注入的 `ensureReady()`。用户点击生成即代表按需使用后端，因此离线时自动执行同一启动流程；测试未注入启动器时保持原行为。

### 测试

- 健康实例不会触发 spawn；并发启动只有一次；失败后允许重试。
- 非本机地址、启动参数、进程提前退出、健康超时和日志尾部均有覆盖。
- 生成上传前调用 `ensureReady()`，启动失败不提交任务，不污染作品状态。
- IPC 拒绝非法通道和参数，设置页覆盖启动中、成功和失败状态。
- 最终在真实 SelfLift 包上启动 ComfyUI，确认 `127.0.0.1:8188/system_stats` 与 `object_info` 可用，所需节点存在；不执行真实视频生成。
