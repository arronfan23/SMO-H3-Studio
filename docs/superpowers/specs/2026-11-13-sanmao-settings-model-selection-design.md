# 三脚猫设置集中化与模型切换设计

## 目标

将三脚猫请求地址、API Key、模型获取和连接测试统一移动到设置页。三脚猫聊天页只保留当前模型切换、对话、停止和新建会话，并支持上游不提供模型列表时手动输入模型 ID。

## 设置页信息架构

- 新增“AI 服务”分组，内部区分“文字润色”和“三脚猫”，不改变两套服务的协议和密钥。
- 文字润色保留现有 OpenAI 兼容配置；三脚猫使用独立的 Claude/Anthropic 兼容配置，任何一边修改都不得覆盖另一边。
- 三脚猫设置包含请求地址、API Key、获取模型、模型选择/手动输入、测试连接和保存按钮。
- API Key 为只写字段，已保存时显示状态但不回显。请求地址、模型和密钥的修改必须明确显示“有未保存修改”。
- 地址或密钥变化后，旧模型列表标记为过期，不再自动作为新地址的可用模型；用户可重新获取或手动输入。

## 模型获取与兜底

- 获取模型只依赖请求地址和 API Key，不要求先选择模型。
- 主进程向上游请求标准模型列表，保留已有 `/v1` 路径，避免重复拼接。Anthropic 官方兼容请求使用 `x-api-key` 和必要的 `anthropic-version` 头，密钥不得进入 URL、日志或错误。
- 仅接受结构正确的模型 ID 数组，去重、排序并过滤空字符串。禁止把任意响应字段或远端说明直接渲染为 HTML。
- 上游不支持列表、鉴权失败、超时或返回格式错误时，保留当前模型并显示脱敏错误；用户可展开手动输入模型 ID。
- 手动输入与列表选择共用同一个当前模型字段，不需要上游支持模型发现。

## 保存与运行时生效

- 保存三脚猫配置后，聊天页立即收到最新地址和模型，无需重启。
- 模型切换只修改当前配置中的模型，复用已保存密钥，不重复要求输入。
- 三脚猫服务在每次新请求开始时读取最新凭据，因此模型切换影响后续消息，不改变正在生成的旧回复。
- 正在回复时禁用模型切换；停止或回复完成后恢复。切换模型不清空当前对话。
- 连接测试可使用当前未保存输入，但不会因此覆盖已保存配置。

## 三脚猫页面

- 顶栏包含助手名称、连接状态、当前模型下拉框、刷新模型和新建会话。
- 请求地址、API Key、获取模型和连接测试不再出现在聊天页。
- 未配置时显示“前往设置”按钮；点击直接打开设置页的三脚猫配置。
- 模型下拉框显示当前模型，可搜索当前地址下的模型；模型名称过长时截断并提供完整名称提示。
- 刷新模型使用已保存配置，不覆盖用户当前选择，除非该模型已不存在且用户确认改选。
- 新建会话与模型切换互不修改对方状态。

## 视觉与交互规范

- 延续现有工作台的白色、中性灰和品牌绿，不引入渐变、装饰光斑或营销式大卡片。
- 顶栏采用固定高度和稳定控件尺寸，模型变化、连接状态和回复状态不得导致按钮跳动。
- 消息列表使用舒适阅读宽度；用户消息使用轻微品牌绿，助手消息使用白底细分隔，长词和代码内容必须可换行。
- 输入区保持固定基线并随内容有限增高，发送、停止和新建会话使用统一图标与提示。
- 窄窗口和 200% 缩放下，模型控件可换行，消息和输入框不得互相遮挡。

## 测试与验收

- 配置测试覆盖独立存储、密钥复用、脱敏和地址变更后的模型过期。
- 模型发现测试覆盖 `/v1` 拼接、鉴权头、去重、超时、非法响应和手动输入兜底。
- 服务测试证明下一条请求使用新模型，正在运行的请求不被改写。
- UI 测试覆盖设置保存、获取/搜索模型、手动输入、前往设置、模型切换、回复中禁用和切页保留。
- 运行类型检查、完整回归、Studio E2E 和打包验证；不包含用户既有环境向导修改。
- 真实模型获取与对话需要有效 Claude 授权；没有授权时明确报告未做真实连接验收。
