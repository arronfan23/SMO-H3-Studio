# 制作台导航与多参考媒体生成设计

日期：2026-11-11

## 目标

将语音、图像、视频入口迁移到左侧“制作台”二级目录，并完成本地 TTS 的 Windows 文件系统兼容、参考音频录制、Qwen 多参考生图、H3 无参考/多参考视频和作品资产流转。

## 已确认范围

- Qwen Image 2.1 参考生图最多 4 张图片。
- H3 图片生视频最多 9 张参考图。
- 文生视频不再强制数字模特；图片生视频中的当前模特只是一张可选参考图。
- 参考生图支持原生 2K 输出。
- 声音克隆支持直接录制参考音。

## 左侧导航

“制作台”是可展开父目录，使用展开/收起图标和 `aria-expanded` 描述状态。展开后显示“语音 / 图像 / 视频”三个二级按钮，点击后进入制作台并切换到对应模式。制作台内部不再重复显示这三个主 tab，现有草稿保持挂载，不因目录展开、收起或页面切换而丢失。

视频内部继续保留“文生视频 / 图片生视频 / 音频数字人”三个细分类，键盘导航、焦点和 ARIA 关系保持完整。语音和图像不需要数字模特，只有文生视频也不再强制模特。

## TTS Windows 兼容

当前错误来自 uv 在 exFAT 的 G 盘创建 Python minor version link directory。`UV_PYTHON_INSTALL_DIR` 改为 NTFS 上的应用专用 Python 安装根目录，默认位于 `%LOCALAPPDATA%\SMO-H3-Runtime\python`，保留显式测试覆盖路径的能力。模型文件、uv 工具、下载缓存和 venv 仍按组件目录管理，不修改 ComfyUI Python。

准备过程必须验证目标 Python 的真实可执行文件和版本，失败后可重试，不把旧的部分安装误判为就绪。取消和关闭语义保持现有行为，不删除用户其他目录或模型。

## 语音

固定音色和声音克隆沿用现有 Qwen3-TTS 服务。克隆面板在现有选择/拖入之外复用 `AudioRecorder`，提供录制、停止、计时、试听、重录和移除参考音。录音输出为受管 WAV，走与数字人录音一致的授权和媒体预览路径，不上传云端。

## 图像

### 文字生图

保留当前 Qwen Image 2.1 标准工作流、提示词、随机种子和 1-100 步控制，不强制参考图。

### 参考生图

新增独立模式，使用 Qwen Image 2.1 多图编辑工作流，而不是把参考图拼到纯文字生图节点上。支持 1-4 张图片，逐张选择、拖入、预览、删除和排序编号 `<image1>` 至 `<image4>`。用户提示词可说明每张图的用途及希望保留/改变的内容。

参考图必须经主进程授权。工作流按数量连接 `TextEncodeQwenImage21.images.image_1..N` 和 VAE，使用参考编辑潜变量及 KSampler，不使用文字生图的空 latent 分支。参考输出支持预览、作品管理和“导入数字模特”。

### 分辨率

图像分辨率新增 2MP、4MP 选项，1:1 时分别对应约 1448×1448 和 2048×2048（实际值按 32 像素网格计算）。默认仍为 1MP。非 1:1 比例按总像素和宽高比计算，不为追求 2K 而拉伸原图。视频分辨率选项不变。

## 视频

### 文生视频

使用无参考图的 H3 文生视频工作流，不再强制 `avatarId` 或上传模特照片。保留提示词、AI 润色、Skill、时长、分辨率、随机种子和步数。

### 图片生视频

使用 H3 Ref2VA 工作流。参考图数量 1-9 可调，逐张选择、拖入、预览和删除。当前模特可作为其中一张参考图，但不是必需输入。按数量上传并连接 `MiniMaxH3ReferenceToVideo.ref_images.ref_image_1..N`，提示词引用 `<Picture 1>` 至 `<Picture 9>`，不能继续假设只有一张参考图。

图片生视频保留提示词、时长、分辨率、随机种子和步数，沿用现有低显存/Spark/低步数修补逻辑。

### 音频数字人

现有上传、拖入、录音、截取、时长、AI 润色、步数及语音作品带入逻辑保持不变。

## 我的作品

### 图像导入数字模特

仅对 `mode === 'image'` 且完成的作品显示“导入数字模特”。点击后以作品标题或短 ID 生成默认模特名，调用现有 `avatars:create` 将图片复制到模特资产目录并选中新模特。原图和作品记录保留，导入不覆盖已有资产，重复导入创建独立副本。

### 筛选层级

主层级为“全部 / 语音 / 图像 / 视频”。选择“视频”后显示第二层级“全部视频 / 文字生视频 / 音频数字人”。状态层级独立为“全部状态 / 运行中 / 已完成 / 失败”，可与主层级和视频子类型组合。继续不显示“等待中”入口，筛选按钮提供 `aria-pressed`。

## 数据与请求

扩展现有请求而不破坏旧作品：

- 文生视频允许 `avatarId = null`，不需要参考图。
- 图片生视频使用 `referenceImagePaths: string[]`，长度 1-9；当前模特可包含在数组中。
- Qwen 参考生图使用 `referenceImagePaths: string[]`，长度 1-4。
- 旧 `text` 视频请求仍包含 `avatarId`，按原 Ref2VA 行为读取；新请求需要明确区分无参考文生视频与参考视频。
- 所有数组使用严格 Zod schema，限制长度、文件类型和真实授权，不接收任意未授权路径。

## 安全与清理

- 多图选择和拖入必须通过 Electron `webUtils` 与主进程授权，不能只靠前端路径字符串。
- 上传文件按 workId 暂存，成功、失败、取消和重试均清理临时副本。
- 输出仍按 workId 和实际计数器命名，保留 finalizing 失败后的删除能力。
- 导入模特复制资产，不删除作品、原图或用户参考图。
- 模型、运行时和用户素材不进入安装包。

## 测试与验收

- 单元测试覆盖 NTFS Python 路径、录音复用、参考图数量、授权、请求 schema、工作流连接和旧请求兼容。
- 渲染测试覆盖二级导航、焦点、草稿、参考图增删、筛选组合及导入模特。
- Electron E2E 使用模拟多图输出，验证 UI 和真实 IPC，不依赖真实模型下载。
- 真实验收包括：当前 G 盘 exFAT 的 TTS 能力加载、克隆录音、Qwen 1/4 张参考图及 2K、H3 无参考文生视频、H3 1/9 张参考视频和图像导入模特。
