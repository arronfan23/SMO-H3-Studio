# SMO.H3 Studio 0.1.4 设计规格

日期：2026-10-28

## 背景与目标

本次处理 3 个桌面端问题：后端队列与真实进度不一致、整个应用窗口缺少圆角、分辨率只用 MP 展示而不够直观。安装器和登录体系拆为后续独立项目，不在本补丁中实现。

已确认的现场证据：

- 一个旧任务在 30 分钟总超时后被软件标记为失败，但 ComfyUI 仍继续执行，导致新任务排队且没有帧进度。
- 旧任务使用 15 秒、9:16、0.7 MP 和 INT8，高分辨率阶段出现显存工作区不足警告，单步曾接近 15 分钟。
- 旧任务最终在第 31 分钟后完成高分辨率阶段，新任务随后也完成，当前新作品状态为 `done`，进度为 `362/362`，输出文件存在。当前不需要再中断任何任务。
- 当前窗口使用原生 `BrowserWindow` 框架，内部面板圆角不会改变整个窗口的外框。
- H3 `ResolutionSelector` 使用 `megapixels * 1024 * 1024`、比例和 `multiple=32` 计算实际像素，不能直接展示未经计算的 720p 或 1080p。

采用已批准的方案 A：修复队列与阶段反馈、使用无框透明圆角窗口、显示 H3 实际输出像素。

## 范围

### 包含

- ComfyUI 队列对账、阶段化进度、超时后按 `promptId` 清理后端任务。
- 整个应用窗口的圆角、自定义标题栏和窗口控制。
- 按当前比例显示 H3 实际输出宽高像素。
- 单元测试、真实 ComfyUI 测试、窗口与布局 E2E、0.1.4 portable 交付。

### 不包含

- 不在本补丁实现登录、注册、会员或服务器 API。
- 不在本补丁实现完整安装器、模型下载或硬件安装包。
- 不改变 H3 模型、冻结工作流、启动脚本和 `multiple=32` 约束。
- 不通过单纯延长固定超时或增加动画掩盖后端排队。
- 不取消当前已完成的新作品，不删除用户作品或源素材。

## 1. 队列、阶段与超时清理

### 状态数据

- 复用 `Work.metadata`，不迁移 SQLite。增加阶段、阶段更新时间、最后进展时间和可选队列位置；原 `metadata.progress.value/max` 继续保存采样进度。
- 阶段至少区分：本地排队、上传素材、等待 ComfyUI、模型加载/节点执行、采样、读取输出与收尾。
- `JobCoordinator` 的本地 `running` 不再直接等同于 ComfyUI 正在执行。界面根据阶段显示「本地排队」「等待 ComfyUI」等文字，队列位置已知时显示前方任务数。
- 显示已用时间和最后更新时间。长时间没有新帧时展示慢任务提醒，不伪造百分比。

### ComfyUI 对账

- `waitForCompletion` 继续处理 WebSocket 的 `progress`、`execution_success`、`execution_error` 和 `execution_interrupted`，并接收 `execution_start`/`executing` 作为后端开始信号。
- 增加周期性 `/queue` 与 `/history` 对账，默认每 5 秒一次。即使错过 WebSocket 事件，也能识别排队、执行中和已完成状态。
- 对账只读取并保存必要状态，不把完整提示词、用户素材或节点内容写入日志。

### 精确取消与超时

- 为 ComfyUI 取消能力增加可选 `promptId`。排队中的目标任务通过 `/queue` 删除；正在运行的目标任务才通过 `/interrupt` 中断；目标已不存在时不操作。
- 不传 `promptId` 时保留现有应用关闭取消行为。传 ID 时不得仅凭全局 `/interrupt` 误杀后来启动的其他任务。
- 用户取消和超时都走同一精确清理路径，先清理后端，再记录最终失败状态。
- 用 30 分钟「持续无任何进展」超时替代固定 30 分钟总时长；有效阶段或队列变化会刷新无进展计时。
- 增加默认 2 小时总上限作为失控兜底，并允许通过主进程选项为测试覆盖。15 分钟无新帧只提示，不直接判失败。

## 2. 整个应用窗口圆角

- `BrowserWindow` 使用 `frame: false`、`transparent: true` 和透明背景，保留现有图标、最小宽高和 preload 安全配置。
- 页面根容器使用透明外部背景与 12px 圆角内容容器，四角真正裁切，不是内部面板视觉效果。最大化时取消圆角，还原后恢复。
- 新增与现有视觉一致的标题栏：品牌区可拖动，最小化、最大化/还原和关闭按钮使用 Lucide 图标，交互区域不拖动。
- 新增严格 IPC 用于窗口最小化、最大化/还原、关闭和最大化状态查询；渲染层不能直接访问 Electron 或 Node。
- 双击标题栏切换最大化，窗口按钮有工具提示和可访问名称。保留现有关闭服务清理流程。
- 验证窗口选项、IPC、1280×820、960×640、200% Zoom 和最大化还原布局，并在当前 Windows 桌面上目检真实四角。

## 3. 具体像素分辨率

- 保留内部 `ResolutionMegapixels`、比例和工作流副本参数，不把 UI 改成任意自由输入像素。
- 新增与 H3 `nodes_resolution.py` 一致的纯函数：使用 1024×1024 基准、当前比例、`multiple=32` 和 Python 的 half-to-even 舍入计算宽高。
- 分辨率下拉不再显示 MP，而显示当前比例对应的实际 `宽 × 高 px`。切换比例时选项同步更新，选中值仍保持 0.4、0.7 或 1.0 MP 内部值。
- 16:9 的现有 3 档应显示：864×480、1152×640、1376×768；9:16 对应交换宽高。不得把这些值替换成看似常见但不符合节点输出的尺寸。
- 单元测试覆盖比例、半值舍入和现有默认档，硬件副本与重试行为不变。

## 4. 验证与交付

- 先用失败测试复现：超时后旧任务未清理、新任务排队显示运行中、错过 WebSocket 完成事件、窗口缺少无框透明配置、UI 仍显示 MP。
- 使用模拟 ComfyUI 验证 `/queue` 删除、运行中 `/interrupt`、目标不存在时不变，以及不会中断后来的无关任务。
- 使用真实 ComfyUI 做健康和必要节点检查，不执行新的真实用户素材视频生成。
- 运行完整单测、类型检查、普通 E2E、package E2E 和真实 LLM 回归。
- 完成规格与代码质量审查后发布 0.1.4，更新正式 `release`、桌面快捷方式和 PR #1。
