# SMO.H3 Studio 整体 UI 与交互调整设计

日期：2026-10-31

## 背景与目标

用户希望改进托盘、制作台、数字模特、作品和设置五个区域的整体交互，同时修复字幕无效、润色收尾报错、作品资产清理不完整和 Windows 中文乱码等实际问题。

本次以桌面工作流的一致性和可验证行为为目标，不改变 MiniMax H3 模型、冻结工作流、ComfyUI 运行包、模型下载清单或 LLM 凭据存储方式。已确认移除画面内字幕功能，不增加字幕烧录或语音识别。

## 当前事实与根因

- 关闭最后一个窗口会直接退出应用，没有托盘生命周期。
- 音频数字人只有原始动作提示词，缺少文字模式已有的 AI 润色流程；Skill 默认值为 `auto`。
- 字幕复选框只向 H3 提示词追加文本，没有独立字幕渲染保证。用户决定删除该功能。
- 分辨率目前只有 0.4、0.7、1.0MP 三档。
- 部分 Skill 输出包含对白，但没有符合当前校验器要求的中英文收尾声明，连续修复后出现 `Missing narration tail`。
- 模特照片只能通过文件对话框选择，拖放路径尚未获得主进程媒体授权。
- 作品只有模特名，没有独立标题和完成时间。删除逻辑只处理单个 MP4/WebM 输出，未覆盖同任务生成的图片和其他关联资产。
- Windows 硬件检测依赖 PowerShell 输出编码，中文系统版本可能发生乱码。
- 硬件设置要求用户逐步点击检测、推荐和应用，并直接展示 `preset`、`lowvram`、`tiling` 等术语，使用场景不清楚。

## 范围

### 包含

- 关闭到托盘、托盘恢复和真正退出的完整生命周期。
- 音频数字人 AI 润色、默认 Skill、更多分辨率和移除字幕入口及行为。
- 对 `Missing narration tail` 的定向兼容与修复。
- 数字模特照片拖放、授权、预览和移除。
- 作品独立标题、完成时间、耗时显示、重命名和关联资产删除。
- Windows 中文编码修复和硬件设置流程简化。
- 数据迁移、单元测试、集成测试、E2E 和打包验证。

### 不包含

- 不实现字幕、字幕烧录、语音识别或口播稿转写。
- 不实现登录、会员或服务器账号系统。
- 不改变 H3 模型、运行包、冻结工作流或模型发布方地址。
- 不使用真实用户素材做生成测试，不中断当前健康的 ComfyUI 后端。
- 不重命名实际视频文件，避免破坏已有输出路径和重试记录。

## 1. 托盘生命周期

- 点击窗口关闭按钮时隐藏窗口，不退出应用，不停止生成任务、ComfyUI 或环境安装流程。
- 托盘使用现有 SMO 图标，提供“打开 SMO.H3 Studio”和“退出程序”。
- 点击托盘图标或“打开”时，恢复已有窗口；窗口不存在时重新创建。
- `window-all-closed` 不再直接退出。只有托盘“退出程序”触发现有 `before-quit` 清理，并且服务只关闭一次。
- 托盘菜单和生命周期拆分为可测试模块，覆盖关闭隐藏、恢复、退出清理和重复调用。

## 2. 制作台

### 音频数字人 AI 润色

- 复用文字模式的“原文 / 润色结果”交互，允许编辑润色结果后再生成。
- 请求包含动作提示词、实际截取时长、`<Picture 1>` 和 `<Audio 1>` 标签；不向 LLM 发送音频文件或音频内容。
- 默认模式使用现有 Ref2VA 流程，不新增文字生成音频能力。
- 润色失败保留原文，生成失败保留当前音频、提示词和选项。

### Skill 与分辨率

- 文字模式默认 Skill 改为 `h3-prompt-writing`，界面显示“通用视频创作”；`auto` 仍可作为手动选项保留。
- 分辨率档位调整为 0.3、0.4、0.55、0.7、0.85、1.0、1.2MP，默认保持 0.7MP。
- 继续通过现有 `ResolutionSelector` 和 `resolveH3Resolution` 计算具体像素，不另写一套像素算法。
- 高负载档位只描述负载，不声称新增硬件配置已实测。

### 移除字幕

- 删除字幕复选框、字幕提示词追加逻辑和新任务中的字幕入口。
- 旧作品元数据可以继续读取；重试旧作品时不再注入字幕提示词。
- 不增加任何替代字幕功能。

### 润色收尾修复

- 收尾校验兼容中英文同义声明，避免把符合“最后 2 秒无旁白”的中文输出误判为失败。
- 当唯一剩余问题是 `Missing narration tail` 时，使用定向修复要求或结构化修复补充正确收尾。
- 不跳过字段缺失、对白被修改、时间戳错误、交互式输出或其他合同错误。
- 修复仍受现有尝试次数限制，并保留原始用户内容。

## 3. 数字模特照片拖放

- 选择照片区域同时支持文件对话框和单文件拖放，显示拖放高亮、预览、文件名和移除按钮。
- 仅接受现有 PNG、JPG、JPEG、WebP 扩展名；多文件拖放给出明确错误。
- 拖放路径必须经过主进程校验和媒体授权，不能直接绕过 `MediaRegistry`。
- 保存、失败和移除行为复用现有逻辑，不因拖放产生额外副本或未经批准的读取。

## 4. 我的作品

### 标题与完成时间

- `works` 表新增可空 `title` 和 `completedAt` 列，采用现有 `PRAGMA table_info` + `ALTER TABLE` 迁移方式。
- 新完成作品记录实际 `completedAt`；旧记录为空时回退到最后执行状态时间，缺少时间时不显示耗时。
- 标题为空时继续显示模特名，保证旧作品兼容。
- 耗时使用 `completedAt - createdAt`，格式化为秒或分秒，不展示失败作品耗时。
- 重命名只修改作品显示标题，不修改 `outputPath`、ComfyUI 历史或实际文件名。

### 删除关联资产

- 删除前收集并校验当前作品的视频路径和同 `workId` 的关联输出，支持已有的视频、图片及实际生成的附属文件。
- 仅处理输出目录内、与当前 `workId` 精确匹配或以其允许前缀开头的常规文件，禁止目录穿越、符号链接逃逸和误删其他作品。
- 保留模特原图、用户上传素材和其他作品文件，不递归删除整个输出目录。
- 先校验全部候选，再执行删除，最后删除数据库记录。删除失败时保留作品记录并显示真实错误。

## 5. 设置

### Windows 编码

- 在硬件检测 PowerShell 脚本中显式设置控制台 UTF-8 输出，再继续解析 JSON。
- 增加中文 Windows 版本输出测试，确保不是仅修改界面显示文本。

### 硬件配置逻辑

- 流程改为“检测硬件 → 自动给出推荐 → 用户确认后应用”，移除单独的“获取推荐”步骤。
- 推荐结果使用中文说明模型策略、显存策略、分辨率和平铺方式，以及它们的适用场景。
- 明确说明配置在下一次生成时生效，不改变正在运行的任务和已有作品。
- 保留恢复默认和模型目录设置，应用前仍需用户确认。
- 低显存、均衡和高显存候选继续使用现有 `recommendHardware`，不重写硬件推荐规则。

## 6. 数据流与兼容性

- 新作品标题、完成时间、请求元数据和执行状态继续保存在本地 SQLite，不上传服务器。
- 旧数据库打开时自动补充新列，不改变已有 ID、输出路径、头像或生成记录。
- 新 IPC 只接受必要字段，作品重命名、拖放授权和托盘操作分别进行严格参数校验。
- 不修改现有环境安装、运行包下载、硬件门禁和 `ready` 提交流程。

## 7. 测试与验收

- 先为每项行为编写失败测试，再实现最小代码使其通过。
- 单元测试：分辨率、润色收尾、作品迁移/重命名/耗时、资产删除边界、拖放授权、托盘生命周期和 Windows 编码。
- 集成测试：音频润色参数、作品删除后磁盘与数据库一致、旧作品重试不带字幕注入。
- E2E：关闭到托盘与退出差异、照片拖放、音频润色、作品改名和设置页中文显示。
- 完整执行 `npm test`、`npm run typecheck`、`npm run test:e2e`、打包态测试及 `git diff --check`。
- 只有真实测试通过后才更新 portable 和桌面快捷方式；未实测的硬件继续标为候选。
